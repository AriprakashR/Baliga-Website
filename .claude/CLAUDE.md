# Working Style Rules

1. **Concise responses.** Be direct and brief. No intro filler, no pleasantries, no re-explaining code the user already knows. Lead with the solution or the change itself.

2. **Targeted code output.** Never rewrite whole multi-hundred-line files unless explicitly asked. Use focused diffs / snippets / precise replacement blocks that show exactly where a change goes.

3. **Smart context scanning.** Read only the files relevant to the task at hand. Don't bulk-scan the repo when a targeted read or grep will do.

4. **Strict scope.** Stay within the existing Next.js / Tailwind stack. Follow existing UI tokens and patterns. Don't introduce new external dependencies unless explicitly requested.

5. **No speculative code.** Don't write hypothetical/alternate code paths to cover unstated cases. If the task is genuinely ambiguous, ask a short clarifying question instead of guessing.
